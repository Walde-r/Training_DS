# Модель прогнозирования стоимости жилья для агентства недвижимости

## Описание проекта

Дипломный проект по курсу «Специализация Data Science».

**Цель:** Построить модель прогнозирования стоимости жилья на основе реальных данных с порталов недвижимости США и разработать веб-сервис для получения предсказаний.

**Задачи:**
1. Провести разведывательный анализ и очистку данных
2. Выделить наиболее значимые факторы, влияющие на стоимость недвижимости
3. Построить модель для прогнозирования стоимости
4. Разработать веб-сервис (FastAPI) для получения предсказаний

## Структура проекта

- **data/** — исходные данные (data.csv)
- **data_processed/** — обработанные данные (data_cleaned_v2.csv, data_features.csv)
- **models/** — сохранённые модели (rf_model_all.pkl)
- **notebooks/** — Jupyter ноутбуки
- **utils/** — вспомогательные модули (cleaners.py, parsers.py)
- **web_service/** — веб-сервис FastAPI (app.py, requirements.txt)

## Ноутбуки

### 00_EDA_initial.ipynb — Разведывательный анализ исходных данных

**Цель:** Исследовать структуру, качество и особенности исходных данных.

**Что сделано:**
- Анализ типов данных и пропусков
- Выявление дублирующихся колонок
- Анализ числовых признаков (baths, beds, stories, sqft)
- Анализ целевой переменной target (цены)
- Визуализация распределений (гистограммы, box plots)
- Анализ сложных полей homeFacts и schools

**Ключевые выводы:**
- target содержит символы $ и ,, требует очистки
- Числовые поля хранятся как строки с текстом ('3 Baths', '2 Beds')
- stories содержит слова ('One', 'Multi/Split')

---

### 01_EDA_and_cleaning_v2.ipynb — Очистка данных

**Цель:** Очистить данные от пропусков, аномалий и выбросов.

**Что сделано:**
- Объединение дублирующихся колонок
- Преобразование числовых полей из строк в числа
- Очистка target от символов $ и ,
- Обработка пропусков (медиана для чисел, мода для категорий)
- Создание признака has_fireplace_info
- Удаление аномалий по методу Тьюки (IQR)
- Ограничение категорий (zipcode, city, state)
- Визуализация распределений до и после очистки

**Результат:** data_cleaned_v2.csv — очищенные данные без пропусков.

---

### 02_feature_engineering.ipynb — Создание признаков

**Цель:** Извлечь новые признаки из сложных полей и нормализовать категории.

**Что сделано:**
- Парсинг homeFacts → year_built, heating, parking, lot_size
- Парсинг schools → schools_count, avg_school_rating, nearest_school_dist
- Нормализация propertyType (1265 → 504 категорий, устранение синонимов)
- Нормализация status (150 → 7 категорий)
- Нормализация street (удаление номера дома, группировка редких улиц)
- Создание признаков: house_age, is_land, rooms_per_1000sqft

**Результат:** data_features.csv — 356,495 строк, 23 колонки.

---

### 03_modeling.ipynb — Моделирование (первая версия)

**Цель:** Обучить модели и сравнить подходы.

**Что сделано:**
- Сравнение трёх подходов: единая модель, каскадная модель, явная стратификация
- Оценка качества по метрикам MAE, R²

**Результаты:**
| Подход | R² |
|--------|-----|
| Единая модель | 0.5448 |
| Каскадная модель | 0.4620 |
| **Явная стратификация по цене** | **0.6222** |

---

### 03_modeling_v2.ipynb — Моделирование и оптимизация (вторая версия)

**Цель:** Продолжить поиск наиболее точной модели с использованием дополнительных методов.

**Что сделано:**
- Валидационная выборка (train/validation/test = 60/20/20)
- Логарифмирование целевой переменной
- Стандартизация данных (StandardScaler, RobustScaler)
- Подбор гиперпараметров (GridSearchCV, Optuna)
- Ансамблевые методы (Stacking)
- Снижение размерности (PCA)

**Результаты:**
| Метод | R² | MAE |
|-------|-----|-----|
| Random Forest (базовый) | 0.5582 | $237,221 |
| Stacking | 0.5753 | $237,669 |
| Optuna + логарифмирование | 0.4511 | $224,742 |
| **Стратификация (из 1-й версии)** | **0.6222** | выше |

**Вывод:** Стратификация по цене остаётся лучшим подходом. Optuna привёл к переобучению.

### 04_web_service.ipynb — Создание веб-сервиса

**Цель:** Разработать веб-сервис для получения предсказаний.

**Что сделано:**
- Создание папки web_service
- Разработка app.py на FastAPI
- Создание requirements.txt
- Реализация полной предобработки входных данных
- Загрузка обученной модели
- Создание эндпоинтов: GET /, GET /health, POST /predict

**Результат:** Работающий веб-сервис на http://localhost:8000

## Запуск веб-сервиса

**Шаг 1.** Перейти в папку web_service:
cd web_service

**Шаг 2.** Установить зависимости:
pip install -r requirements.txt

**Шаг 3.** Запустить сервер:
python app.py

**Шаг 4.** Открыть в браузере:
http://localhost:8000/docs
